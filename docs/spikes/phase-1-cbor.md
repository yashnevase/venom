# Phase 1 deterministic CBOR report — 2026-11-15

## Task, phase and commit

Implement the specified deterministic CBOR codec within Phase 1. Base commit
is 3668b41 on phase-1/protocol-core. The implementation commit and remote CI
result are provided in the final handoff. Encryption retains the owner's review
gate, and offline-hotspot testing is pending by their earlier decision.

## Implementation choices

The agent selected RFC 8949 section 4.2.1 core deterministic encoding from the
prior ADR recommendation, and cborg 7.0.0 from the draft's named candidate.
ADR 003 records this choice, dependency size/license/audit information and the
integer/value subset. Each API caller supplies byte, container-depth and token
budgets. The test caps are test conditions rather than protocol parser defaults.

Encoding snapshots supported values and checks encoded length before final
serialization. Decoding uses a bounded tokenizer, strict syntax checks, Maps,
and a canonical re-encoding comparison. Plain input objects normalize to Maps.
Exact message schemas and version dispatch belong to the gated protocol parsers.

## Tests run

The acceptance test was written before source and failed for the missing module.
The first implementation then had 7 passing tests while the vector file was
being prepared. The completed codec has 8 passing acceptance/property/fuzz tests.
Tests cover deterministic ordering, integer boundaries, Unicode/BOM, duplicate
keys, invalid UTF-8, indefinite and truncated input, unsafe JavaScript values,
accessors, input isolation, cycles, graph expansion, declared sizes and budget
edges. Map-order vectors distinguish the RFC 8949 bytewise ordering.

The independent Python implementation encodes the same 26 debug fixtures from
the standard. Its outputs match the golden bytes and TypeScript encoder. The
TypeScript decoder accepts and canonically round-trips each golden vector.
The existing 8 Tag vectors retain their independent Python verification.

Final local checks include 1 foundation acceptance test, 17 Vitest tests and
3 browser regression tests, 21 tests total. Strict types, builds, typed lint,
independent vectors, dependency licenses and diff checks are part of the gate.

## Measured

Mac arm64, Node v24.11.0. A standalone run through the compiled ESM exports
exercised the same seed 0x4f4d0001, 2500 generated byte strings and 2500 bit-mutated
canonical seeds. It completed 5000 inputs in 40.495 ms. The slowest decode was
0.357 ms. 1418 valid canonical inputs round-tripped byte-for-byte and 3582 inputs
returned rejection results. The raw observation is phase-1-cbor-fuzz.json.
Timing is one local observation. Mutation can produce valid CBOR, with payload
authentication to be supplied by the future encryption module.

The built public ESM entry point encoded and decoded a byte-bearing record.
cborg adds 202342 compressed package bytes, 838511 unpacked package bytes and
zero transitive runtime dependencies. Its license is Apache-2.0. The advisory
audit reported 0 findings across 166 locked dependencies. The local installed
license check inspected 136 package versions. App-bundle size is a later measure.

## Not verified on a real device

Codec conformance and fuzzing ran in Node. Browser and phone execution need
verification. Camera, storage, offline-hotspot delivery and encrypted profile
interoperability were outside this codec test.

## Claims ledger rows added or changed

VEC-CBOR/CBOR-ORDER/CBOR-BOUNDARY record deterministic bytes and round trips.
CBOR-STRICT/CBOR-LIMIT/CBOR-GRAPH/CBOR-INPUT/FUZZ-CBOR record the tested rejection
and resource-budget cases. Their scope is local Node execution.

## Known problems

An independent audit of cborg 7.0.0 has not been established. This codec supplies
serialization and bounded parsing. Phase 1 still requires reviewed identity,
sealed-box, receipt and streaming schemas, crypto decisions and their vectors.
The owner gate and D-8 cryptographer review are documented in ADR 002.
